We (Mozilla Firefox) are considering the Web Bluetooth API (Firefox bug 2022433) and thus request adding the Web Bluetooth API in the DAS WG charter "Tentative Deliverables" as follows:

Web Bluetooth API
An API to discover and communicate with devices over the Bluetooth 4 wireless standard using the Generic Attribute Profile (GATT).
Draft state: Draft Community Group Report
Adopted Draft: Adopted from Web Bluetooth Community Group
Note: This work may turn into a joint deliverable with the Web Applications Working Group.

Comment by Marcos Cáceres (@marcoscaceres) at 2026-04-08

WebKit's published position on Web Bluetooth is oppose. The rationale: "The low-level nature of this API means that it is insecure, has a massive privacy risk, and perhaps most importantly doesn't meet the web platform's device-independence bar."

As with WebUSB, the device-independence concern is the structural one. A permission model improvement can reduce security risk, but it cannot make an application work on a device that lacks the underlying Bluetooth hardware or where Bluetooth access is OS-mediated. That bar has not moved since the WICG incubation.

Adding this as a tentative deliverable implies a path to Recommendation, and the W3C Process asks whether "there are independent interoperable implementations of the current specification" before a spec advances.

What has changed in the API design or permission model — relative to what the Web Bluetooth CG has been incubating — that would make standardization in DAS viable?

Comment by Reilly Grant (@reillyeon) at 2026-05-12

A permission model improvement can reduce security risk, but it cannot make an application work on a device that lacks the underlying Bluetooth hardware or where Bluetooth access is OS-mediated. That bar has not moved since the WICG incubation.

There are plenty of devices without underlying camera, audio or gamepad hardware and yet no such argument is leveled against those APIs. The fact is that the majority of consumer devices these days provide the necessary Bluetooth hardware and their operating systems provide applications with APIs at the same level of abstraction as Web Bluetooth. There is no implementability concern here.
